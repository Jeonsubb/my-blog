# 좁아진 신입 문, 운영 증거로 돌파하라

2025–2026년 한국 백엔드·인프라 채용 시장은 한마디로 "개발자 수요는 남아 있지만 신입 몫은 급격히 줄었다"로 요약된다. 2025년 상반기 개발자 공고 약 10만 건 중 서버/백엔드가 16.2%로 가장 많았지만, '신입'으로 명시된 공고는 0.8%였고 지원서의 29.5%는 신입이 냈다. 네이버는 2026년 상반기에 7년 만에 처음으로 개발자 공채를 건너뛰었다. 한국 백엔드 공고의 기술 표준은 여전히 Java/Kotlin + Spring Boot + JPA + MySQL(금융권은 Oracle)이다. 우대사항은 Redis·Kafka·대용량 트래픽·MSA·장애 대응이라는 거의 같은 어휘로 반복된다. 클라우드/인프라(DevOps·SRE·플랫폼) 공고는 AWS 위의 Kubernetes, Terraform 같은 IaC, ArgoCD, Prometheus/Grafana를 요구한다. 다만 제품 회사의 인프라 공고는 대부분 5~15년 차를 찾기 때문에, 신입은 MSP·SI 공채나 기업 연계 교육, 또는 백엔드로 입사한 뒤 옮기는 경로로 들어간다. AI는 기본기를 대체하기보다 평가 방식을 바꾸고 있다. 일부 기업은 AI 사용을 허용하고 "AI 결과를 검증하는 능력"을 보지만, 대형 플랫폼 다수는 여전히 AI 금지 알고리즘 테스트를 본다. 그래서 신입에게 가장 효율적인 전략은 Spring 백엔드를 주력으로 삼고, 그 백엔드를 직접 배포·관측·장애 대응해 본 "운영 증거"를 인프라 역량으로 덧붙이는 것이다. 지금의 Next.js·Supabase 블로그는 실제 트래픽과 실제 보안·LLM 비용 문제를 가진 살아 있는 서비스다. 이미 문서로 정리해 둔 Spring 하이브리드 전환을 실행하면서 rate limit, CI, AWS 배포, 모니터링을 붙이면, 공고가 요구하는 문법과 거의 그대로 겹치는 포트폴리오가 된다.

## 신입 전용 공고 0.8%에 지원서 29.5%가 몰린다

수치부터 보면 백엔드는 가장 많이 뽑는 직무이면서 가장 붐비는 직무다. 사람인·점핏이 2025년 상반기 개발자 공고 약 10만 건과 지원 약 260만 건을 분석한 결과, 서버/백엔드는 **전체 공고의 16.2%로 1위**였고 **지원의 23.5%**를 가져갔다. DevOps/시스템 엔지니어는 공고의 11.1%, 지원의 10.2%였다. 경력 요건별로 보면 **5~10년이 39.7%**로 가장 많았고 **신입 전용 공고는 0.8%**에 그쳤다. 반면 지원서는 **신입이 29.5%로 최대 집단**이었다 ([이투데이](https://www.etoday.co.kr/news/view/2500510)). 0.8%는 '신입'으로만 표기된 공고를 센 수치로 보인다. '경력무관'이나 '0~3년' 공고는 다른 범주로 잡혔을 가능성이 커서, 실제 문호가 이 숫자만큼 좁지는 않다. 그래도 다른 지표들이 같은 방향을 가리킨다. 한국노동연구원은 SW 개발자 공고 중 신입 비중이 **2022년 53.5%에서 2024년 37.4%로** 16.1%p 떨어졌다고 분석했다. 같은 분석에서 2024년 3년 미만 개발자는 9,000명 줄었고 3년 이상은 42,000명 늘었다 ([트윅](https://www.twig24.com/news/2026/01/06/20260106500238)). 원티드랩의 2026 채용 트렌드 조사(인사담당자 153명)에서도 기업이 가장 많이 뽑겠다고 답한 연차는 **4~7년 차(49.7%)**였고 신입은 **12.4%**에 그쳤다 ([지디넷코리아](https://v.daum.net/v/20251208161412362)).

대형 IT 기업의 움직임은 이 숫자를 구체적으로 보여준다. 2025년 2월 조사에서 네카라쿠배당토 중 신입 개발자 공채를 계획한 곳은 네이버 하나였다. 나머지는 "별도 신입 채용 계획 없음, 필요 시 상시채용"이라고 답했다 ([바이라인네트워크](https://byline.network/2025/02/12-386/)). 그 네이버도 **2026년 상반기에는 7년 만에 처음으로 개발자 공채를 열지 않았고**, 8월 중순까지 하반기 계획도 없었다 ([한국금융신문](https://www.fntimes.com/html/view.php?ud=202608141444496947094b7542a8_18)). 카카오의 신규 채용은 2023년 452명에서 2025년 292명으로 35% 줄었다. 연 수백 명의 개발자를 길러 내던 네이버 부스트캠프도 2026년 운영을 멈췄다 ([에너지경제신문](https://ekn.kr/web/view.php?key=20260819028084086)). 한국은행은 2022년 6월부터 2026년 6월 사이 줄어든 청년 일자리 28만5천 개 중 **26만8천 개(94%)**가 AI 노출도가 높은 산업에서 나왔다고 분석했다. 컴퓨터 프로그래밍·SI 업종의 청년 고용은 **16.6%** 감소했다. 다만 한국은행은 AI를 유일한 원인이 아니라 이미 약해지고 있던 경력 사다리의 **'가속 요인'**으로 규정했다. 팬데믹기 과잉 채용의 정상화와 경력직 선호가 먼저 있었다는 설명이다 ([아이뉴스24](https://www.inews24.com/view/1995762)).

그렇다고 시장이 무너진 것은 아니다. 원티드 조사에서 개발은 여전히 기업들이 가장 집중해 뽑겠다는 직군(28.1%)이었고, 74.5%가 채용 규모를 유지하거나 늘리겠다고 답했다 ([지디넷코리아](https://v.daum.net/v/20251208161412362)). 2025년 2월 OKKY의 채용 결정권자 조사에서 신입을 뽑겠다는 기업이 가장 많이 찾은 직무는 **백엔드(38%)**였고 인프라는 7%에 불과했다. 신입 채용을 망설이는 이유로는 경기 침체와 함께 **"즉시 기여할 사람이 필요하다"(35%)**가 꼽혔다 ([바이라인네트워크](https://byline.network/2025/02/12-386/)). 정리하면 백엔드는 신입 수요가 가장 많지만 지원자도 가장 많이 몰리는 직무이고, 기업이 원하는 신입은 "가르쳐야 할 신입"이 아니라 "바로 일할 수 있는 신입"이다. 이 두 가지가 아래 준비 전략의 전제다.

## 백엔드 공고의 표준 문법은 여전히 Java·Spring·JPA다

한국 대형·핀테크 기업의 백엔드 공고는 놀라울 만큼 획일적이다. 토스페이먼츠 서버 개발자 공고의 스택은 Java, Kotlin, Spring MVC/WebFlux/Batch, JPA, Spring Cloud Gateway, MySQL, Redis, Elasticsearch, Kafka, Oracle이다. 우대사항은 "Java 기술 생태계(Kotlin/Spring/JPA)에 대한 이해도와 엔지니어링 역량(OOP/TDD/Refactoring)", "Redis와 Kafka를 사용한 경험", "RDBMS에 대한 높은 이해도"다 ([토스 채용](https://toss.im/career/job-detail?job_id=5028079003)). 배민 그로스 프로덕트팀은 Java 또는 Kotlin + Spring Boot + JPA를 필수로 두고 대용량 트래픽 아키텍처 경험을 우대한다 ([직행](https://zighang.com/recruitment/9a210b88-a097-4f0a-a444-23a80028eb7a)). 카카오페이 2025 경력 서버 개발자 공고는 JVM 언어 서버 개발과 **운영 장애 대응 경험**을 필수로 요구했다 ([링커리어](https://linkareer.com/activity/255993)). 카카오페이 머니서비스는 Spring Cloud 기반 MSA 설계, 장애 복구 시나리오, **RDBMS 쿼리 최적화와 인덱스 튜닝**을 요구했다 ([비즈니스피플](https://www.bzpp.co.kr/biz/businessDetailView/BR251119A00262)). 2024년 이후 눈에 띄는 변화는 언어 1위가 바뀐 것이 아니다. **Kotlin이 Java와 대등한 위치로 올라섰다**는 점이다. 당근페이는 "Kotlin·Spring Boot 기반 JVM 환경"을 명시한다 ([당근 채용](https://about.daangn.com/jobs/4511184003/)).

우대사항의 어휘도 거의 정해져 있다. **Redis + Kafka**는 토스 계열 공고에 거의 같은 문장으로 반복되는 우대 조합이다. **대용량 트래픽**은 토스·배민·쿠팡·카카오 같은 소비자 대상 서비스의 공통 키워드다. 핀테크는 여기에 **트랜잭션과 유량제어**를 더한다. 토스뱅크 계정계 공고는 Oracle·MySQL 기반 DB 설계 경험과 "트랜잭션과 유량제어 방법론"에 대한 이해를 요구한다 ([토스 채용](https://toss.im/career/job-detail?job_id=5939812003)). 반면 확인한 공고 중 DDD를 명시한 곳은 없었다. 한국에서 널리 쓰이는 QueryDSL도 공고 문구에 따로 등장하지 않았다. 공고가 말하는 엔지니어링 품질은 주로 "OOP, TDD, 클린 코드, 리팩토링"이라는 표현으로 나온다.

기업 유형별로 보면 핵심 스택은 같고 도메인 요구가 차이를 만든다. 금융 SI 공고는 "java / sql / Unix / Oracle / 전자정부프레임워크"처럼 구체적인 레거시 도구와 SI 프로젝트 연차를 하드 필터로 건다 ([더팀스](https://www.theteams.kr/recruit/wanted/1909901)). 증권사 차세대 프로젝트 협력사 공고는 C, Pro-C, ProFrame까지 요구한다 ([직행](https://zighang.com/recruitment/f9307885-e16c-40c9-acc9-80fd7a64ed6f)). 스타트업은 스택이 가장 다양하다. 원티드 백엔드 공고를 모아 보여주는 페이지에는 **TypeScript/NestJS + PostgreSQL(Supabase) + Prisma + AWS(ECS/SQS/S3/Lambda) + Redis/BullMQ** 조합이 있다. 재시도·멱등성을 고려한 비동기 작업 설계를 요구하는 공고와, 주니어에게 AI 코딩 도구가 만든 코드를 설명할 수 있느냐고 묻는 공고도 함께 나온다 ([RBYE](https://rbye.vercel.app/t/server)). 당근 부동산팀처럼 "TypeScript, Go, Java, Kotlin, Python, Ruby 중 하나 이상"이면 되는 언어 무관 공고도 있다 ([당근 채용](https://careers.daangn.com/jobs/role/5296522003/)).

| 커머스·플랫폼(배민, 쿠팡) | Java/Kotlin, Spring Boot, JPA | 대용량 트래픽, AWS, gRPC | 성능 개선, 분산 시스템(쿠팡은 시니어 위주) |
| 금융 SI·은행 | Java, SQL, Oracle, Unix | 해당 도메인 경험 | 전자정부프레임워크, ProFrame, SI 프로젝트 연차 |
| 스타트업 | TypeScript/NestJS, Python, PHP 등 다양 | Redis/BullMQ, AWS 관리형 서비스 | 재시도·멱등성, AI 도구로 서비스를 출시한 경험 |
| 대기업 신입 공채 | 스택 무관 코딩테스트 | 없음 | CS 기본기, 알고리즘 구현력 |

한국 공고는 글로벌 흐름과 뚜렷하게 다르다. Stack Overflow 2026 조사에서 Java는 사용률 27.6%에 비해 "쓰고 싶다"는 응답이 **13.1%**에 그쳤다. Spring Boot 사용률은 12.8%였다. 데이터베이스는 PostgreSQL이 사용 57.9%, 희망 43.9%로 압도적이었고 MySQL은 전년보다 5%p 넘게 줄었다 ([Stack Overflow 2026](https://survey.stackoverflow.co/2026/technology/data)). 하지만 한국에서 취업하는 사람에게 기준은 한국 공고다. 마지막으로 확인된 정량 통계인 점핏 2022년 결산에서도 Java가 공고의 **35.7%**로 1위였다 ([파이낸셜뉴스](https://www.fnnews.com/news/202301050929529152)). 흥미로운 신호는 연봉이다. 점핏의 2025 이직자 연봉 분석에서 백엔드 스택별 평균은 C++ 5,748만원, PHP 5,339만원, Python 5,078만원이었다 ([전자신문](https://www.etnews.com/20251031000354)). Java는 5,005만원, Spring Boot는 4,739만원으로 더 낮았다 ([브랜드뉴스](https://www.ibrandnews.com/news/articleView.html?idxno=11086)). 표본이 이직자에 한정돼 약한 신호이긴 하지만, 한국에서 Java/Spring은 "희소한 차별점"이 아니라 **"입장권"**이라는 해석과 맞는다. 즉 없으면 대형·금융 공고의 대부분에서 탈락하지만, 있다는 것만으로 돋보이지는 않는다. 한 가지 분명히 해 둘 점이 있다. 2025–2026년 한국 백엔드 공고의 **스택별 점유율 통계는 어느 플랫폼에서도 찾지 못했다**. 인터넷에 도는 "백엔드 공고의 60~70%가 Java+Spring"이라는 수치는 출처를 확인할 수 없어 이 보고서에서 쓰지 않았다.

## 인프라 공고는 5년 차 이상을 찾고, 신입은 우회로로 들어간다

클라우드/인프라 공고의 기술 요구는 선명하다. 다만 제품 회사의 인프라 공고는 신입에게 거의 열려 있지 않다. 토스플레이스 SRE는 7~15년 ([리멤버](https://career.rememberapp.co.kr/job/posting/330118)), 토스플레이스 DevOps는 6~15년 ([원티드](https://www.wanted.co.kr/wd/322625)), 부릉 DevOps는 5년 이상을 요구한다 ([원티드](https://www.wanted.co.kr/wd/389174)). 카카오엔터프라이즈의 KakaoCloud 기술지원 직무도 Linux 5년, 클라우드 2년 이상 경력을 걸었다 ([리멤버](https://career.rememberapp.co.kr/job/posting/259789)). 확인한 공고 거의 전부가 **Kubernetes**를 요구했고, 대부분 **AWS(EKS)** 위에서 운영하는 경험을 원했다. 부릉 공고 하나에 2026년 인프라 표준 스택이 거의 다 들어 있다. AWS(EKS, EC2, S3, RDS, CloudFront, Lambda), Terraform, Jenkins/ArgoCD/GitHub Actions, Datadog/Prometheus/Grafana/ELK, Python/Shell/Go 자동화, SLI/SLO 대시보드, **FinOps 기반 비용 최적화**, 개발 생산성을 위한 내부 플랫폼 도구 개발이 모두 나온다 ([원티드](https://www.wanted.co.kr/wd/389174)). 토스 계열은 여기에 Istio 서비스 메시를 더한다. 토스플레이스 DevOps는 "IaC 및 Policy as Code"와 개발자가 직접 인프라를 다루는 셀프서비스 플랫폼을 요구하고, 안정성·성능·보안·**비용** 사이의 트레이드오프 판단을 명시한다 ([원티드](https://www.wanted.co.kr/wd/322625)).

이 공고들에서 가장 중요한 신호는 **SRE가 사실상 코드를 짜는 엔지니어**라는 점이다. 토스페이먼츠 SRE는 Java/Kotlin + Spring 개발 역량, 성능 테스트와 병목 해결, "리눅스 및 네트워크 시스템에 대한 깊은 이해"를 함께 요구한다 ([리멤버](https://career.rememberapp.co.kr/job/posting/253702)). 토스플레이스 SRE는 하나 이상의 언어로 프로덕션 코드를 짤 수 있어야 하고 SLI/SLO 정의와 포스트모템을 다룰 수 있어야 한다 ([리멤버](https://career.rememberapp.co.kr/job/posting/330118)). 백엔드 공고가 Docker·Kubernetes·AWS를 우대하고 인프라 공고가 Spring을 요구하면서, 두 직군의 경계는 양쪽에서 흐려지고 있다. "플랫폼 엔지니어링"은 한국에서 아직 별도 직함보다는 DevOps 업무 안의 셀프서비스·GitOps·내부 도구로 나타난다. 확인한 한국 공고 중 Backstage나 OpenTelemetry를 명시한 곳은 없었다. 글로벌에서는 Kubernetes 프로덕션 사용률이 컨테이너 사용 조직의 **82%**에 이르렀다 ([CNCF](https://www.cncf.io/announcements/2026/01/20/kubernetes-established-as-the-de-facto-operating-system-for-ai-as-production-use-hits-82-in-2025-cncf-annual-cloud-native-survey/)). OpenTelemetry는 도입률 76%에 비해 프로덕션 사용이 **41%**에 머문다 ([Grafana Labs](https://grafana.com/blog/observability-survey-OSS-open-standards-2026)). IaC는 Terraform이 사용 18.3%로 OpenTofu(3.6%)를 크게 앞선다 ([Stack Overflow 2026](https://survey.stackoverflow.co/2026/technology/data)). 신입이 IaC를 하나만 배운다면 Terraform이 안전한 선택이다.

클라우드 사업자 선택은 민간과 공공에서 갈린다. 민간에서는 AWS가 기본 통화다. 국내 클라우드 이용 기업의 **60.2%가 AWS를 쓰고 51.5%가 AWS를 주 사업자로** 두며, 네이버클라우드가 이용률 20.5%로 국산 1위다 ([IB토마토](https://newstomato.com/ReadNews.aspx?no=1258941)). 공공은 다르다. 네이버·KT·NHN 클라우드가 공공 클라우드 시장의 **약 80%**를 차지한다. AWS는 2025년 3월에야 CSAP '하' 등급을 받았고, '중·상' 등급은 사실상 국내 사업자의 영역으로 남아 있다 ([아이뉴스24](https://www.inews24.com/view/1829903)). 공공 SI나 MSP를 노린다면 NCP 경험이 의미가 있다. 제품 회사를 노린다면 AWS가 우선이다.

신입이 인프라로 들어가는 현실적인 문은 MSP, IT 서비스 대기업 공채, 채용연계형 교육이다. 국내 클라우드 매출은 2024년 9조2,609억원으로 25.2% 늘었고, 그중 MSP(관리형 서비스) 매출이 **31.4%**로 가장 빠르게 성장했다 ([경기일보](https://www.kyeonggi.com/article/20260330580494)). 메가존클라우드·베스핀글로벌·메타넷엑스는 "AI 인프라 허브"로 사업을 바꾸는 중이다 ([MTN](https://news.mtn.co.kr/news-detail/2026042215434561189)). 메가존의 채용연계형 KDT 과정은 TCP/IP·라우팅·Linux부터 Docker/K8s, AWS VPC/EC2/RDS, Terraform, GitLab CI/CD, GPU·MLOps 모듈까지 984시간을 가르친다 ([더팀스](https://www.theteams.kr/activities/page/346493/le)). 이 커리큘럼은 MSP가 신입에게 기대하는 범위를 잘 보여준다. 신입 인프라 공고가 "클라우드 엔지니어"보다 "DevOps/시스템 관리자"나 "시스템엔지니어(SE)"라는 이름으로 올라오는 경우가 많다는 점도 검색할 때 기억해 둘 만하다 ([캐치](https://www.catch.co.kr/NCS/RecruitInfoDetails/558726)). 카카오엔터프라이즈가 TAM·CSP SE·MSP 경력을 우대하는 것을 보면 "MSP → CSP·제품 회사" 경로도 실제로 존재한다 ([리멤버](https://career.rememberapp.co.kr/job/posting/259789)). 자격증은 이 경로에서만 의미가 있다. 확인한 제품 회사 인프라 공고 중 자격증을 필수나 우대로 건 곳은 하나도 없었다. 현업자들은 신입에게 AWS SAA 정도를 권하면서도 프로젝트 깊이가 자격증 개수보다 중요하다고 말한다 ([코멘토](https://comento.kr/job-questions/%EC%82%BC%EC%84%B1%EC%A0%84%EC%9E%90/%EB%84%A4%ED%8A%B8%EC%9B%8C%ED%81%AC/%EB%8C%80%EA%B8%B0%EC%97%85_%ED%81%B4%EB%9D%BC%EC%9A%B0%EB%93%9C_%EC%A7%81%EB%AC%B4%EB%8A%94_%EC%9E%90%EA%B2%A9%EC%A6%9D%EC%9D%B4_%ED%95%84%EC%88%98%EC%A0%81%EC%9D%B8%EA%B0%80%EC%9A%94-549804)).

그렇다면 백엔드 지망생은 인프라를 어떻게 다뤄야 할까. 공고 대비 지원 비율로 보면 DevOps/시스템 엔지니어(공고 11.1%, 지원 10.2%)는 백엔드(공고 16.2%, 지원 23.5%)보다 공고 하나당 경쟁이 덜하다 ([이투데이](https://www.etoday.co.kr/news/view/2500510)). 하지만 그 공고 대부분이 시니어용이고, 신입 인프라 수요는 7%로 가장 낮다 ([바이라인네트워크](https://byline.network/2025/02/12-386/)). 운영 자체를 좋아한다면 MSP·SI 신입으로 시작하는 경로가 충분히 합리적이고 경쟁도 덜하다. 그러나 이미 Spring 전환 계획과 금융 IT 지향을 가진 사람에게는 **백엔드를 주력으로 두고 인프라를 차별점으로 얹는 쪽**이 더 맞다. 토스 SRE가 Spring 개발자를 뽑는다는 사실은, 백엔드로 입사해 운영 역량을 쌓은 사람이 나중에 SRE·플랫폼으로 옮기는 경로가 열려 있음을 뜻한다. 반대 방향은 그보다 어렵다.

## AI는 기본기를 지우지 않고 시험지를 바꾸고 있다

2025–2026년 한국의 채용 평가는 두 모델로 갈라졌다. 첫째는 감독하에 AI를 금지하는 알고리즘 테스트다. 잡코리아는 2026년 5월 "네이버, 카카오 등 대부분"이 여전히 코딩테스트에서 AI를 금지한다고 정리했다 ([잡코리아](https://www.jobkorea.co.kr/recruit/careers/articles/ai-enabled-coding-interview)). 삼성 SW 역량테스트는 약 240분 동안 2문제를 푸는 구현·시뮬레이션 중심 시험으로 알려져 있다 ([링커리어 커뮤니티](https://community.linkareer.com/employment_data/6625027)). 카카오 2026 그룹 공채는 코딩테스트를 두 차례 치렀다 ([카카오 기술블로그](https://tech.kakao.com/posts/814)). 둘째는 AI를 주고 일하는 방식을 보는 실무형 평가다. 컬리는 2025년 개발자 코딩테스트에서 처음으로 ChatGPT류 도구를 허용했다 ([중앙일보](https://v.daum.net/v/20250610060102680)). 무신사는 2026년 신입 채용의 2차 면접에서 모든 지원자에게 OpenAI Codex를 제공했다 ([무신사 뉴스룸](https://newsroom.musinsa.com/newsroom-menu/2026-0205)). 넥슨은 코딩테스트를 없애고 AI 활용 역량평가로 바꿨다. 크래프톤은 자체 도구로 지원자의 소스코드뿐 아니라 **AI 대화 기록과 검증 단계**까지 평가한다 ([더팩트](https://news.tf.co.kr/read/economy/2376557.htm)). 같은 사이클 안에서 두 형식을 모두 만날 수 있으므로 신입은 둘 다 준비해야 한다.

AI를 허용하는 평가가 무엇을 보는지는 꽤 일관된다. 잡코리아는 평가 기준을 **문제 구조화, AI 제어력, 검증 습관, 커뮤니케이션** 네 가지로 정리했다. 문제 형식도 고정된 알고리즘 문제에서 기존 코드베이스를 읽고 버그를 고치고 기능을 추가하는 쪽으로 옮겨 가고 있다고 했다 ([잡코리아](https://www.jobkorea.co.kr/recruit/careers/articles/ai-enabled-coding-interview)). 동아일보가 인용한 CoderPad 조사에서는 응답자의 약 66%가 **AI 결과물의 오류를 찾아내는 능력**을 중시했다. 그러면서도 라이브 코딩 면접에서는 대체로 AI를 허용하지 않고 지원자 스스로 풀 수 있는지를 확인한다 ([동아일보](https://m.news.nate.com/view/20260912n05091)). 다만 이 기사의 원문 일부가 깨져 있어 수치는 원문 확인이 필요하다. 글로벌에서도 Canva가 백엔드 면접의 CS 기초 단계를 "AI 보조 코딩" 면접으로 바꾸면서, AI가 만든 코드의 문제를 찾아 고치는 능력과 코드에 대한 완전한 책임을 평가 항목으로 명시했다 ([Canva Engineering](https://canva.dev/blog/engineering/yes-you-can-use-ai-in-our-interviews)). 네이버도 AI로 문제를 푸는 것만큼 **AI 결과를 비판적으로 검토하고 판단하는 능력**이 중요하다고 밝혔다. 클라우드·보안 같은 도메인 전문성의 비중이 커지고 있다는 업계 평가도 함께 나왔다 ([한국금융신문](https://www.fntimes.com/html/view.php?ud=202608141444496947094b7542a8_18)).

직무 내용에서도 AI는 백엔드 기본기 위에 얹히는 형태다. "Python 백엔드 엔지니어(AI 에이전트)" 공고는 동시성·비동기·장애 격리·Docker·CI/CD를 먼저 요구한다. 그 위에 **LLM API의 비용·지연·품질 트레이드오프**를 다뤄 본 경험과 RAG·에이전트 컴포넌트 설계 경험을 더한다. 업무 설명은 "비결정적이고 지연이 큰 LLM 호출을 안정적으로 처리하는 백엔드 시스템"이다 ([원티드](https://www.wanted.co.kr/wd/361200)). 이 공고는 5년 이상 경력직용이다. 그래도 신입에게 주는 메시지는 분명하다. 새로 필요한 능력은 프롬프트 작성이 아니라 **느리고 비싸고 가끔 틀리는 외부 호출을 안정적으로 운영하는 능력**이다. 원티드 조사에서 "AI·데이터 활용 역량"은 인재 평가 기준 4위(24.2%)였다 ([지디넷코리아](https://v.daum.net/v/20251208161412362)). 미국에서는 AI 스킬을 언급하는 기술 공고 비중이 2024년 1월 15%에서 2026년 5월 **73%**로 뛰었다 ([HR Dive](https://www.hrdive.com/news/dice-report-tech-hiring-AI/824902/)). 그런데 같은 기간 미국 소프트웨어 공고 반등분의 **71%는 시니어** 직무였다 ([Indeed Hiring Lab](https://hiringlab.indeed.com/?p=20708)). Stanford 연구는 AI 노출 직무에서 22~25세 고용이 추세 대비 **19%** 낮다고 분석했고, 그 원인을 해고가 아니라 **채용 감소**로 보았다 ([Stanford Digital Economy Lab](https://digitaleconomy.stanford.edu/publication/canaries-in-the-coal-mine/)). 한국과 미국 모두 주니어 압박은 "덜 뽑는 것"으로 나타난다. 반대로 Claude Code나 MCP 같은 특정 도구명을 요구하는 한국 공고는 확인한 범위에서 거의 없었다. 지금 평가되는 것은 도구 이름이 아니라 도구를 쓰는 방식이다.

AI가 아직 약한 곳이 신입이 차별화할 수 있는 곳이다. Stack Overflow 2026 조사에서 AI 사용자의 73%가 매일 AI를 쓰지만, 프로덕션 시스템의 배포·운영·트러블슈팅에 AI를 쓰는 비율은 **20%**에 그쳤다 ([Stack Overflow](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)). AI 답변을 그대로 쓰는 개발자는 9.6%에 불과했다 ([IT Brief](https://itbrief.com.au/story/stack-overflow-survey-shows-developers-trust-ai-with-caveats)). 직접 측정한 결론은 아니지만, 운영·장애 대응·검증은 코드 생성보다 AI 자동화가 덜 된 영역이다. 앞 절에서 "인프라를 차별점으로 얹으라"고 권한 근거가 여기에도 있다.

## 지금 블로그를 '운영해 본 Spring 백엔드'로 키우는 법

준비 순서는 공고가 거는 필터 순서를 따르면 된다. 첫 번째 층은 협상 불가능한 입장권이다. Java 21 + Spring Boot + JPA, 그리고 SQL을 "쓸 줄 안다"를 넘어 인덱스·트랜잭션·격리 수준을 설명할 수 있는 수준까지 익혀야 한다. 여기에 CS 기본기와 코딩테스트 실력이 들어간다. 금융 IT가 목표라면 Java를 먼저 굳히고 Kotlin은 그다음에 배워도 늦지 않다. 은행·SI 공고가 요구하는 전자정부프레임워크도 Spring 기반이므로 Spring 이해가 그대로 이어진다. 두 번째 층은 "바로 일할 수 있다"는 증거다. JUnit 단위·통합 테스트, GitHub Actions CI, Docker, AWS 기본 구성(VPC, EC2, RDS, IAM), Redis, 그리고 Spring Actuator + Prometheus/Grafana 수준의 관측성이 여기에 해당한다. 세 번째 층은 차별점이다. Kafka 기초, 로컬 Kubernetes 실습, 최소한의 Terraform, LLM 호출 운영 경험이 여기 들어간다. Istio, 카오스 엔지니어링, 멀티 클러스터 운영은 7~15년 차 SRE 공고의 언어이므로 신입이 쫓을 대상이 아니다. 블로그 규모에 Kafka나 Kubernetes를 억지로 넣는 것도 면접에서 "왜 필요했나"라는 질문에 약점이 된다. 필요가 있는 곳에만 쓰고, 나머지는 따로 실험한 뒤 글로 남기는 편이 낫다.

현재 블로그의 진짜 가치는 스택이 아니라 **실제로 운영 중인 서비스**라는 점이다. 배포된 도메인이 있고, 크롤러 트래픽 로그와 관리자 통계 페이지가 있다. 실제로 발견해 고친 보안 문제(댓글 비밀번호 SHA-256 → bcrypt)와 실제 성능 개선(force-dynamic → ISR, 2026-10-13)도 있고, 실제 비용이 드는 LLM 기능도 있다. 교육 업체들의 포트폴리오 조언도 클론 프로젝트보다 직접 기획한 프로젝트에서 겪은 문제를 **수치와 함께** 설명하라고 한다 ([제로베이스](https://zero-base.co.kr/event/media_insight_contents_BE_project)). 토스뱅크 공고도 지원자에게 "해결한 문제, 방법, 결과"와 "기술적 의사결정 과정"을 묻는다 ([리멤버](https://career.rememberapp.co.kr/job/posting/155696)). 다행히 `docs/SPRING-MIGRATION-PLAN.md`에 이미 하이브리드 전환 계획(화면은 Next.js 유지, API만 Spring Boot로 분리, Supabase PostgreSQL에 JPA로 직결)이 6단계로 정리돼 있다. 아래 표는 그 계획을 공고 키워드에 맞춰 다시 배열한 것이다. 블로그의 현재 상태는 2026년 10월 중순 저장소 코드를 직접 확인한 결과다.

| 공고 키워드 | 블로그 현재 상태 | 확장 방향 | 면접에서 보여줄 증거 |
|---|---|---|---|
| Java/Kotlin, Spring Boot, JPA | API 라우트 5개가 Next.js에 있고 전환 계획서가 있음 | 계획서 1~3단계를 실행해 Controller-Service-Repository 구조로 이관하고, 검증 전까지 기존 API와 병행 운영 | 레거시를 멈추지 않고 옮긴 단계적 전환 전략 |
| 보안, Spring Security | 관리자 인증은 직접 만든 HMAC 토큰이고, 댓글 API(`app/api/comments/route.ts`)는 여전히 공개 anon 클라이언트로 DB를 조작함. `PROJECT-NOTES.md` 이슈 1이 실제로 해결됐는지 확인 필요 | Spring Security로 인증을 재구현하고, 쓰기 경로를 서버 단일 통로로 만든 뒤 RLS 잠금 | 취약점 발견 → 수정 → 재발 방지를 다룬 포스트모템 글(bcrypt 전환 포함) |
| Redis, 유량제어 | 공개 AI 엔드포인트 `/api/ai/post`에 호출 제한이 없음(ROADMAP 미완료 항목) | Redis 기반 rate limit, 글(slug)별 AI 결과 캐시, 본문 대신 slug만 받도록 변경 | 적용 전후 LLM 호출 수와 비용 |
| 테스트, CI/CD | 테스트는 게시 파이프라인 1개뿐이고 `.github` 워크플로가 없음 | JUnit 통합 테스트(Testcontainers 등)와 GitHub Actions로 PR마다 빌드·테스트 | 테스트가 막아 준 회귀 사례 |
| Docker, AWS, IaC | Vercel 배포만 있음 | 계획서 6단계의 배포처로 Railway 대신 AWS를 택하고, Dockerfile + 최소 Terraform(VPC, EC2/ECS, RDS 또는 기존 Supabase) 구성 | 아키텍처 다이어그램과 월 비용 내역 |
| 관측성, SLO | `traffic_logs`와 `/admin/stats`가 있음 | Actuator + Prometheus/Grafana, API p95 지연 목표 설정, 부하 테스트 | ISR 전환 전후 응답 시간 같은 숫자 |
| 트랜잭션, 동시성, 멱등성 (금융) | 해당 기능 없음 | 계획서 4절에 적힌 계좌 도메인 모듈을 추가해 이체에 락과 멱등성 키 적용 | 동시 요청 테스트에서 잔액 정합성을 지킨 결과 |
| 비동기, 재시도 | 봇 결과 push용 리포팅 API 구상이 있음(`PROJECT-NOTES.md` B) | 수신과 처리를 큐로 분리하고 재시도·중복 처리 방지 | 실패를 일부러 일으켜 본 테스트 |
| AI 활용, LLM 운영 | Vercel AI SDK + Gemini로 요약·태그·SEO 기능 운영 중 | Spring으로 옮기면서 타임아웃, 폴백, 비용 로깅, 결과 품질 점검 추가 | "AI가 틀린 지점을 어떻게 잡았나"를 다룬 개발 기록 |

이 순서에는 이유가 있다. 2026 하반기 대기업 공채 접수는 이미 끝났으므로, 남은 몇 달은 2027년 상반기 사이클과 그 사이의 수시 기회를 겨냥한 준비 기간으로 쓰는 것이 맞다. 앞쪽에는 Spring 전환 1~4단계와 테스트·CI, 그리고 rate limit을 둔다. 이 묶음이 입장권(Spring)과 보안·유량제어 경험을 한 번에 증명하고, 남아 있는 실제 위험도 줄여 준다. 그다음에 AWS 배포·관측성과 금융 도메인 모듈을 붙이면 핀테크·금융 IT 공고의 "트랜잭션·장애 대응" 언어와, 인프라 공고의 "AWS·IaC·SLO" 언어가 같은 프로젝트에서 동시에 나온다. 이 기간 내내 코딩테스트 연습은 따로 계속해야 한다. 대부분의 주요 기업이 여전히 AI 없이 푸는 알고리즘 시험을 1차 관문으로 쓰기 때문이다. 각 단계는 블로그 시리즈로 연재한다. 그러면 전환 계획서가 의도한 대로 학습 기록과 포트폴리오가 동시에 쌓이고, 크래프톤식 평가가 보는 "검증의 흔적"도 자연스럽게 남는다.

현재의 TypeScript 스택을 버릴 필요도 없다. 스타트업 공고에는 NestJS + PostgreSQL(Supabase) + Prisma 조합이 실제로 나오고 ([RBYE](https://rbye.vercel.app/t/server)), 토스 NEXT에도 Node.js 트랙이 있었다 ([토스피드](https://toss.im/tossfeed/article/2025next)). 화면은 Next.js로 두고 API만 Spring으로 옮기는 하이브리드 구조는 대기업·금융 트랙(Spring)과 스타트업 트랙(TypeScript)에 모두 대응한다. 실무에서 가장 흔한 "React/Next.js + Spring Boot" 조합이기도 하다. 자격증은 MSP·SI 트랙을 함께 볼 때 AWS SAA 하나 정도면 충분하다. 그 시간을 프로젝트의 운영 깊이에 쓰는 편이 제품 회사 공고에는 훨씬 효과적이다.

## 결론

이번 조사에서 가장 크게 바뀐 이해는 "백엔드냐 인프라냐"가 신입에게 사실상 잘못된 질문이라는 점이다. SRE 공고는 Spring 개발 역량을 요구하고, 백엔드 공고는 Kubernetes·AWS·장애 대응을 우대한다. AI가 가장 덜 침투한 영역은 프로덕션 운영과 검증이다. 그래서 두 시장 모두에 통하는 하나의 프로필이 있다. "Spring 백엔드를 직접 만들고, 클라우드에 올리고, 관측하고, 문제가 났을 때 원인을 추적해 기록한 사람"이다. 기업이 신입을 꺼리는 이유는 "바로 기여할 사람이 필요해서"인데, 이 프로필은 그 반대 증거를 정면으로 제시한다. 신입이 경쟁에서 이기는 수단은 스택 목록을 늘리는 것이 아니라 운영 경험의 깊이를 보여주는 것이다.

블로그 프로젝트에 대해서도 같은 결론이 나온다. 경쟁력은 Next.js나 Supabase라는 선택에서 나오지 않는다. 실제 사용자와 크롤러, 실제 취약점, 실제 LLM 비용을 가진 살아 있는 서비스라는 데서 나온다. 클론 프로젝트로는 만들 수 없는 "만들었다"와 "운영했다"의 차이가 곧 공고가 시험하는 차이다. 불확실성도 남아 있다. 2025–2026년 한국 공고의 스택별 점유율 통계는 공개되지 않았다. 네이버·카카오의 공채 재개 여부와 주요 기업의 코딩테스트 AI 정책도 아직 유동적이다. 그러니 2027년 상반기 공채 공고가 나오면, AI 허용형 평가가 컬리·무신사·게임사 밖으로 퍼졌는지부터 확인하고 준비의 무게를 조정하는 것이 좋다.
